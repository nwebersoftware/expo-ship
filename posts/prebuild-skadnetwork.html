Prebuild deleted my SKAdNetwork IDs

No error. No warning. Ads still serve. You simply stop being able to measure them.

SKAdNetworkItems is the list of ad networks permitted to receive install attribution on iOS. AdMob alone publishes around fifty entries. Miss them and the SDK does not complain, App Review does not care, and revenue looks fine — while installs stop being credited to campaigns and every CPA number becomes fiction.

How it disappears

You add the list by hand to ios/App/Info.plist. Campaigns work. Then you run:

npx expo prebuild --platform ios

Prebuild regenerates ios/ from app.json. Anything hand-edited into the native project is gone, including the SKAdNetwork list, because app.json never contained it. The app still builds. Nothing in the output mentions the plist diff.

Check for it in one line

plutil -extract SKAdNetworkItems json -o - ios/App/Info.plist | jq length
# Error: No value at that key path   ← it is gone

Put it where prebuild can see it

expo.ios.infoPlist is copied verbatim on every prebuild:

{
  "expo": {
    "ios": {
      "infoPlist": {
        "SKAdNetworkItems": [
          { "SKAdNetworkIdentifier": "cstr6suwn9.skadnetwork" },
          { "SKAdNetworkIdentifier": "4fzdc2evr5.skadnetwork" }
        ]
      }
    }
  }
}

The same rule covers every plist key you care about: NSUserTrackingUsageDescription, URL schemes, ITSAppUsesNonExemptEncryption, ATS exceptions. If it lives only in ios/, it lives until the next prebuild.

Verify the archive, not the source tree

A build setting can override a plist key on the way through, so check the thing you actually upload:

plutil -extract SKAdNetworkItems json -o - \
  build/App.xcarchive/Products/Applications/App.app/Info.plist | jq length

We shipped three builds without the list and did not notice until an audit compared the archive against a September build that still had all fifty entries.
